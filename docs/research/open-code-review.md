# OpenCodeReview (`alibaba/open-code-review`) — research notes

Primary-source research on `alibaba/open-code-review`, gathered from the repository itself (README, LICENSE, `AGENTS.md`, `action.yml`, in-repo docs under `pages/src/content/docs/en/`), the GitHub REST API, the npm registry, and the project's docs site. All stats captured **2026-11-19**. Companion notes: [pr-agent.md](./pr-agent.md).

## 1. Identity, what it is, and repo health

- Canonical repo: `alibaba/open-code-review` — https://github.com/alibaba/open-code-review; website https://open-codereview.ai (https://api.github.com/repos/alibaba/open-code-review).
- Description: "Secure, fast, efficient, battle-tested at Alibaba's scale. Hybrid architecture code review tool: deterministic pipelines + LLM Agent, precise line-level comments, built-in multi-language ruleset (NPE, thread-safety, XSS, SQL injection), OpenAI & Anthropic compatible" (https://api.github.com/repos/alibaba/open-code-review).
- What it is: an AI-powered **code review CLI** (`ocr`). README says it "originated as Alibaba Group's internal official AI code review assistant — over the past two years, it has served tens of thousands of developers and identified millions of code defects," then was open-sourced. It reads Git diffs, sends changed files to a configurable LLM agent with tool use, and emits structured, line-level review comments; `ocr scan` reviews whole files for auditing (https://github.com/alibaba/open-code-review/blob/main/README.md).
- Maintainer: owned by the `alibaba` GitHub organization; npm package maintainers are `lizhengfeng.lzf` and `ninan.nn` (`@alibaba-inc.com`) (https://registry.npmjs.org/@alibaba-group/open-code-review/latest). Top contributors by commits include `lizhengfeng101` (307), `chethanuk` (40), `wu21-web` (38), `Qiyuanqiii` (25) (https://api.github.com/repos/alibaba/open-code-review/contributors?per_page=10).
- Age and size: created **2026-05-18** (about six months old at capture); **54,276 stars**, **4,490 forks**, **161 watchers**, **334 open issues** (https://api.github.com/repos/alibaba/open-code-review). README carries Trendshift weekly/monthly trending badges and a self-declared OpenSSF Gold badge (https://github.com/alibaba/open-code-review/blob/main/README.md).
- Activity: **not abandoned** — last push **2026-11-19T09:30:09Z**, repo updated 2026-11-19 (https://api.github.com/repos/alibaba/open-code-review). Releases are near-daily: v1.13.10 (2026-11-15), v1.13.11 (2026-11-17), v1.13.12 (2026-11-18), v1.13.13 (2026-11-19) (https://api.github.com/repos/alibaba/open-code-review/releases?per_page=10).
- Governance artifacts exist at the repo root (`GOVERNANCE.md`, `ASSURANCE_CASE.md`, `ROADMAP.md`, `CONTRIBUTING.md`), i.e. more structure than a typical one-person tool (https://api.github.com/repos/alibaba/open-code-review/contents).
- Benchmark claims are **self-reported**: versus general-purpose agents, higher precision/F1 at ~1/9 the tokens and faster, but deliberately **lower recall**; benchmark is AACR-Bench (50 repos, 200 PRs, 10 languages, 1,505 annotated issues) (https://github.com/alibaba/open-code-review/blob/main/README.md, https://huggingface.co/datasets/Alibaba-Aone/aacr-bench).

## 3. Tech stack and runtime requirements

- Core is **Go** (module `github.com/alibaba/open-code-review`); the GitHub API reports `language: Go` (https://api.github.com/repos/alibaba/open-code-review, https://raw.githubusercontent.com/alibaba/open-code-review/main/AGENTS.md). Building from source needs **Go ≥ 1.26.10**, Git, Make; `make build` writes `dist/opencodereview` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md).
- Distribution is an **npm wrapper**: `@alibaba-group/open-code-review` version 1.13.13 at capture; `bin/ocr.js` downloads a signed, checksum-verified platform binary from GitHub Releases; `engines.node >= 14` in the manifest, while the docs' QuickStart lists **Node.js ≥ 18** and **Git ≥ 2.41** (https://registry.npmjs.org/@alibaba-group/open-code-review/latest, https://raw.githubusercontent.com/alibaba/open-code-review/main/package.json, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/quickstart.md, https://github.com/alibaba/open-code-review/blob/main/README.md).
- Five documented install methods: npm, Homebrew (`brew install open-code-review`), `curl … install.sh`, direct GitHub Release binary (darwin/linux/windows × amd64/arm64), and build from source (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md). **No Docker image or webhook server is documented** in the installation docs (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md) — unlike PR-Agent, which ships Docker images and FastAPI webhook apps (https://github.com/The-PR-Agent/pr-agent#docker-hub-namespace-migration, https://docs.pr-agent.ai/overview/supported_platforms/).
- LLM backends: OpenAI-compatible (`openai`, `openrouter`, `gemini`, `dashscope`, `deepseek`, `kimi`, `z-ai`, `xai`, Azure-compatible gateways, Ollama/vLLM, etc.), Anthropic (`anthropic`), AWS Bedrock (`anthropic-bedrock`), OpenAI Responses API (`openai-responses`), plus a ChatGPT sign-in preview (`chatgpt`) (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/configuration.md).
- API keys: most providers need one — e.g. `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY`, `XAI_API_KEY`, `DASHSCOPE_API_KEY`, `MOONSHOT_API_KEY` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/configuration.md). Bedrock uses the AWS credential chain; `chatgpt` uses `ocr auth login`; custom providers require an explicit (placeholder allowed) `api_key`; keys can instead come from a secret manager via `api_key_cmd` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/configuration.md).
- **Delegation mode is the zero-extra-key path**: OCR does file selection/rule resolution only and the host coding agent (Claude Code, Codex, Cursor, Open Code, Qoder, etc.) performs the review with its own subscription/model (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/integrations/delegate.md). This does **not** apply to the GitHub Action, which still requires an LLM endpoint and token (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
- Models must support **native tool calling**; models that merely narrate tool calls in text cannot work (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md).
- State is local-only: `~/.opencodereview/config.json`, `~/.opencodereview/rule.json`, JSONL session transcripts under `~/.opencodereview/sessions/`, plus committed `<repo>/.opencodereview/rule.json` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md). Optional OpenTelemetry telemetry never exports prompt/response content; `content_logging` is a dead flag (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md).

## 4. Installation and running

### CLI (exact commands from source)

```bash
npm install -g @alibaba-group/open-code-review   # or: brew install open-code-review
ocr config provider          # guided provider/key/model setup + connectivity test
ocr config model             # switch models
ocr llm test                 # verify endpoint
cd your-project
ocr review                                  # workspace: staged + unstaged + untracked
ocr review --from main                       # current branch since diverging from main
ocr review --from main --to feature-branch   # merge-base range
ocr review --commit abc123                   # single commit
ocr scan [--path dir]                        # full-file audit, no git history needed
ocr review --format json --audience agent > result.json
ocr delegate preview && ocr delegate rule <paths...>   # delegation mode
```
(https://github.com/alibaba/open-code-review/blob/main/README.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/quickstart.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/integrations/delegate.md)

Agent-skill install: `npx skills add alibaba/open-code-review` (native) or `--skill open-code-review-delegate`; plugins exist for Claude Code, Codex, Cursor, Kimi Code, and OpenCode (https://github.com/alibaba/open-code-review/blob/main/README.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/integrations/agent-skill.md).

### GitHub Action (exact snippet from the repo's example)

```yaml
# .github/workflows/ocr-review.yml
- uses: alibaba/open-code-review@main
  with:
    llm_url: ${{ secrets.OCR_LLM_URL }}
    llm_auth_token: ${{ secrets.OCR_LLM_AUTH_TOKEN }}
    llm_model: ${{ vars.OCR_LLM_MODEL }}
    llm_use_anthropic: ${{ vars.OCR_LLM_USE_ANTHROPIC }}
```
Secrets `OCR_LLM_URL` and `OCR_LLM_AUTH_TOKEN` plus variables `OCR_LLM_MODEL` and `OCR_LLM_USE_ANTHROPIC` are required; `GITHUB_TOKEN` is automatic with `pull-requests: write` (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md). The action is a 57 KB composite `action.yml` that installs the OCR CLI from npm at run time (`ocr_version`, default `latest`), checks out the PR with `fetch-depth: 0`, computes the merge base, runs `ocr review --from <merge-base> --to <head> --format json`, and posts comments (https://raw.githubusercontent.com/alibaba/open-code-review/main/action.yml, https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md). For reproducibility, pin both the action to a full commit SHA *and* `ocr_version` (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).

## 5. Git providers and GitHub PR support

- **Git-only**: FAQ states non-Git VCS (SVN/Mercurial) is not supported — diff providers shell out to `git` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md).
- CI examples shipped in-repo: GitHub Actions, GitLab CI, Bitbucket Pipelines, GitFlic CI, Gerrit (Jenkins/Gerrit Trigger), and Alibaba Codeup CI (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/README.md).
- **GitHub PRs are a first-class target**: the workflow uses `pull_request_target` (`opened`/`synchronize`/`reopened`) plus optional `issue_comment` triggers (`/open-code-review`, `@open-code-review`), resolves PR numbers, fetches PR head blobs, and posts to the PR via the review API (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
- Output modes include `--format json` and `--format sarif` (SARIF 2.1.0 for GitHub Code Scanning) (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/cli-reference.md).

## 6. What it reviews and how results are posted

- Pipeline: bootstrap → git diff (workspace/commit/range) → six-gate file filter → semantic file grouping (max 10 files/group) → per-group sub-agent with optional plan phase + up to N review rounds (`effort`: low=1, medium=2, high=3) → line resolution, re-location and an LLM review filter → text/JSON (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/configuration.md).
- Built-in per-language/system rules include TS/JS/TSX/JSX, `package.json`, GitHub Actions workflow YAML, JSON/YAML, Go, Python, Rust, SQL, Prisma, etc.; the repo description advertises NPE, thread-safety, XSS and SQL-injection rules (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md, https://api.github.com/repos/alibaba/open-code-review).
- Default exclusions matter for this project: `**/*.test.{js,jsx,ts,tsx}`, `**/*.spec.*`, `**/__tests__/**`, `**/node_modules/**`, `**/dist/**`, `**/.next/**`, lock/secrets paths, and any extension outside the allowlist; a diff over 80% of `max_tokens` is skipped as `too_large` (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md).
- GitHub Action posts **both** a sticky summary issue comment (updated in place; "🔍 OpenCodeReview found N issue(s)" with inline/summary/skipped/failed counts) and **inline review comments** on "Files changed", including GitHub `suggestion` blocks when a fix is available; comments without line info fall back into the summary (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md). `sticky_summary`, `incremental`, `checkpoint_range`, `resolve_outdated`, and `upload_artifacts` are all configurable (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
- As a local CLI, results are text, JSON, or SARIF to stdout/file; no PR-comment posting (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/cli-reference.md).

## 7. Configuration and repo-specific conventions

- Four-layer rule chain (first match wins): `--rule` flag → `<repo>/.opencodereview/rule.json` (explicitly "safe to commit") → `~/.opencodereview/rule.json` → embedded system rules (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md).
- Rule file is **JSON** with `include`, `exclude`, and `rules: [{path, rule, merge_system_rule}]` glob entries (doublestar syntax, case-insensitive) (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md). The project itself commits such a file at `.opencodereview/rule.json` to enforce provider-registry conventions (https://raw.githubusercontent.com/alibaba/open-code-review/main/.opencodereview/rule.json).
- Business context can be injected with `ocr review --background "..."` or `--background-file <markdown>`; the **GitHub Action exposes only a `background` input** (no `background-file`) and a `rule` input pointing to a JSON file (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/cli-reference.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/action.yml).
- **No automatic AGENTS.md / CLAUDE.md ingestion is documented** in the docs or `action.yml`: primary-source surfaces for project guidance are `rule.json`, `background`, MCP tools, and agent skills (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/action.yml, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md). This matters for DreamDev, whose `AGENTS.md` defines the issue tracker and domain docs — those conventions would have to be restated in JSON rules/background rather than auto-read.
- MCP server support for external business context; prompts and built-in tool definitions are embedded and cannot be overridden at runtime without a source rebuild (https://github.com/alibaba/open-code-review/blob/main/README.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md).

## 8. Limitations, caveats, and security

- **Security posture of the action is explicit and careful**: it uses `pull_request_target` (so secrets exist for forks) but checks out only trusted base code plus PR head blobs, gates comment-triggered reruns by `author_association` (MEMBER/OWNER/COLLABORATOR) and non-bot to stop arbitrary users draining LLM quota, warns **not to point `rule` at a file sourced from the PR branch** when secrets are in scope, and isolates `resolve_outdated` into a job with `contents: write` that never checks out PR code (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
- **Pinning caveat**: the action installs the CLI from npm at run time, so pinning the action ref alone does not freeze behavior; pin a full commit SHA and `ocr_version` (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md). The npm wrapper also auto-updates itself in the background unless `OCR_NO_UPDATE` is set (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md).
- **Code confidentiality**: OCR "sends your diffs (and optional read-tool snippets) to whatever LLM endpoint you configured"; there is no built-in secret redaction, and the guide recommends excluding sensitive paths yourself (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md). Session JSONLs stay local (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md).
- **Coverage caveats**: excluded/binary/generated/too-large files are silently out of scope; `terminal_state: complete` means complete over the *selected* set, not every byte; provider directories (`vendor/`, `node_modules/`) can never be reviewed (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md).
- **Reliability caveats**: sub-agent failures are isolated (partial results, non-zero exit); comments with unanchored line info get `start_line: 0` and are moved to the summary; stale threads can be marked outdated by force-pushes; checkpoint trust boundary is "write-permission holders are trusted" (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/architecture.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
- **Cost/quality caveats**: self-reported benchmark trades recall for precision; cost scales with `effort` rounds, plan phases, up to 100 tool rounds, and memory-compression LLM calls; `--max-tokens-budget` can cap spend (https://github.com/alibaba/open-code-review/blob/main/README.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/faq.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/cli-reference.md).
- **Third-party mirror caveat**: `OCR_GITHUB_MIRROR` downloads both binary and checksum from a third party, so integrity is not guaranteed in mirror mode (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/installation.md).
- **Repo-age risk**: six months old with 334 open issues despite very high stars and daily releases; long-term durability is unproven compared with a 3+ year project (https://api.github.com/repos/alibaba/open-code-review, https://api.github.com/repos/The-PR-Agent/pr-agent).

**Recommendation: adopt PR-Agent as DreamDev's automated PR reviewer first; keep OpenCodeReview as an optional, complementary second pass / local agent skill.**

Rationale, weighted to the stated criteria:

1. **Setup effort** — DreamDev has no CI workflow yet. PR-Agent's single-step action plus one `OPENAI_KEY` is the lowest-friction path to "PR #24 and every future PR gets a review" (https://github.com/The-PR-Agent/pr-agent#github-action-recommended). OCR requires four CI secrets/vars, a `pull_request_target` trust decision, optional comment-trigger gating, and SHA/version pinning to be safe and reproducible (https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
2. **Repo health / risk** — PR-Agent is 3+ years old, community-owned, with steady releases and a documented license history ending at MIT; OCR is six months old with extraordinary growth and near-daily releases but 334 open issues and a still-evolving surface (https://api.github.com/repos/The-PR-Agent/pr-agent, https://github.com/The-PR-Agent/pr-agent/blob/main/LICENSE, https://api.github.com/repos/alibaba/open-code-review). For a dependency that will write to PRs, maturity wins.
3. **Cost / API keys** — both need one LLM key in CI, so this is roughly a tie; PR-Agent's default OpenAI path is the simplest to budget, while OCR's broader provider list (DeepSeek, DashScope, Kimi, etc.) is an advantage only if cost optimization becomes a priority (https://docs.pr-agent.ai/usage-guide/changing_a_model/, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/configuration.md).
4. **Language-agnosticism / repo fit** — both review TypeScript fine; OCR has explicit TS/JS/TSX and `package.json`/Bun-adjacent rules and posts one-click `suggestion` blocks, which is genuinely attractive for a Bun/TypeScript monorepo, but its default exclusions (`*.test.ts(x)`, `node_modules`, `dist`) should be noted (https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/review-rules.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
5. **Conventions fit** — neither tool reads `AGENTS.md` automatically on the CI path, so DreamDev's issue-tracker/domain-doc conventions would need explicit rule config in either case; PR-Agent at least adds no new committed config format (https://raw.githubusercontent.com/alibaba/open-code-review/main/action.yml, https://github.com/The-PR-Agent/pr-agent#github-action-recommended).

**When to add OCR anyway:** if after a few PRs the team wants higher-precision line-level findings, GitHub-native suggestions, checkpointed incremental reviews, or to reuse the existing agent skills without a separate API key locally, install OCR's skill/delegation mode (`npx skills add alibaba/open-code-review`, or `npx skills add alibaba/open-code-review --skill open-code-review-delegate`) alongside PR-Agent — but treat its CI action as a later, deliberate upgrade with the security pinning and `rule.json` work that entails (https://github.com/alibaba/open-code-review/blob/main/README.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/pages/src/content/docs/en/integrations/delegate.md, https://raw.githubusercontent.com/alibaba/open-code-review/main/examples/github_actions/README.md).
